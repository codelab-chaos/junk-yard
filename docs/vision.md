# Junk Yard Vision

Junk Yard is a simple GitHub Pages site that hosts a collection of one-off SPA apps and single `index.html` pages. When I have a random want, need some data, or do a quick bit of research, the result gets built as a small app and dropped into the yard.

## The flow

1. **Create** the app (an SPA or a plain `index.html`).
2. **Catalog** it: add an entry to the root catalog.
3. **Tag** it with a few relevant search terms.
4. **Index** it for deeper, full-text search (content, data, notes), not just tags.
5. **Build and host** it on GitHub Pages, shipping the built bundle.

## Project layout

```
./index.html                  catalog and search (the front door)
./bundle/                     the catalog's built main.js / main.css (committed)
./catalog.json, search-index.json   generated by the build (committed)
./junkyard/{app}/index.html   each app, one folder per app
./junkyard/{app}/main.ts      the app's one source entry
./junkyard/{app}/bundle/      the app's built main.js / main.css (committed)
./junkyard/{app}/app.json     the app's catalog record (title, description, tags, created, keywords)
./assets/                     shared static assets (one copy only)
./src/lib/                    shared TS libraries (search, DOM, clipboard, storage, hash codec)
./build/bundle.ts             builds every bundle and the catalog data
./build/junkyard.ts           discovers apps, builds catalog and search-index content
```

- The root `index.html` is the catalog: lists every app, filters by tag, and searches the index.
- Each app lives at `./junkyard/{app}/index.html` and is reachable at `/junkyard/{app}/` on Pages.

## Catalog and search

- The catalog is data driven: a single manifest (one record per app) holds the name, path, description, tags, and created date. The UI renders from that data, nothing is hand-coded per app.
- A build step generates the search index from the manifest plus each app's content, so deeper search stays in sync without manual upkeep.
- Adding an app means adding a folder with `index.html` and `app.json`. No config edits: the build discovers it, adds it as an entry, and adds it to the catalog and index.

## Assets

- **Never keep two copies of an asset.** Static files, large or small, live once in `./assets`.
- Pages reference them by relative path (`./assets/x` from the root, `../../assets/x` from `junkyard/{app}/`). Bundles live in `bundle/` folders so they never mix with `assets/`.
- Apps share assets by referencing the common path rather than vendoring their own.

## Bundle convention

Every page, the catalog and each app, follows one convention so any bundle is easy to find and debug:

- `index.html` is hand-written and static. It references only `./bundle/main.js` (`type="module"`) and `./bundle/main.css`, plus assets by relative path. No root-absolute URLs, no base setting: a page works from any mount path, including `/junk-yard/`.
- `main.ts` beside it is the single entry. It imports its CSS and shared code (`@lib`, `@styles`).
- `npm run build` writes `bundle/main.js`, `bundle/main.css` and `bundle/main.js.map`: fixed names, no hashes, one file (no code splitting), unminified with a source map.
- Runtime fetches resolve relative to the page (`fetch('../../assets/x')`), never through `import.meta.env.BASE_URL`.
- Bundles are committed. Run `npm run build` before committing source changes.

## Code

- **TypeScript is preferred** for anything with shared logic, so libraries (catalog loading, search, UI helpers, data utilities) can be shared across apps.
- **Plain `index.html` has its place** for small enough one-offs where a build adds nothing.
- Keep concerns separate and each module single-purpose; favor data-driven apps over hard-coded ones.

## Hosting

- GitHub Pages serves the repo root from `main` ("Deploy from branch"). Nothing is built at deploy time, so the committed bundles are the site. `.nojekyll` keeps Pages from processing the files.
- Because bundles are committed, rebuild before every commit that touches source. Bundle names are fixed, so diffs stay readable.
- A page without code can be a plain `index.html` with no `main.ts` or bundle.
